# Week B 글 재작성 공통 브리프 (자기완결형)

이 파일과 에이전트 프롬프트에 적힌 **Day별 지시**만 규칙으로 쓴다. 템플릿, 다른 명세, 다른 Day 글은 열지 않는다. 프롬프트가 이 파일과 충돌하면 프롬프트가 우선한다.

명령은 `app/study_docs`에서 실행한다. 경로에 한글이 있으므로 PowerShell에서 `-Encoding utf8`을 쓴다.

## 근거

- 노트: 담당 폴더의 `vocab.md` · `quiz.md` · `explain-log.md` · `progress.md` 중 있는 것
- 코드: 프롬프트가 지정한 커밋에서 `git show <sha>:<path>`로 읽은 것만 발췌한다. HEAD 코드가 아니다.
- 기존 글의 사실(검증 결과, 오답 원문, 커밋 링크, 측정값)은 보존한다. 형식만 바꾸고 내용은 잃지 않는다.

## 서두

- 제목과 도입 문단은 그대로 둔다.
- 요약 인용블록 바로 뒤에 아래 블록을 넣고 곧바로 첫 H2로 넘어간다. 「이 글의 순서」 목록은 만들지 않는다.

```
> **오늘의 흐름** `A → B → C → …`
>
> 이전 Day: … (DayN)
> 다음 Day: … (DayN)
```

## 개념 소절 형식 (가장 중요)

**모든 개념 H3는 제목 바로 다음 줄에 한 줄 정의 인용블록이 반드시 있어야 한다.** 빠지면 실패다. 예시(Day01에서 가져옴):

````
### 2) 요청 한 건의 처리 순서

> **DispatcherServlet** = Spring MVC 안에서 모든 요청을 먼저 받아, 알맞은 Controller 메서드를 찾아 호출하고 결과를 응답으로 돌려주는 서블릿

우리 코드에는 `DispatcherServlet`이 한 줄도 없다. 아래처럼 `@RestController`와 `@GetMapping`만 붙였는데 요청이 `hello()`에 닿는 이유가 이 서블릿이다.

```java
@RestController
public class HelloController {
    @GetMapping("/hello")   // 시작 시 "GET /hello → hello()" 매핑으로 등록된다
    public String hello() {
        return "Hello,StudyRoom!";
    }
}
```

```text
클라이언트: GET /hello
→ DispatcherServlet이 요청 수신
→ HandlerMapping에 "GET /hello를 처리할 메서드"를 조회
→ HelloController.hello() 호출
```

(설명 문단 · 필요하면 비교 표 · 기존 그림)

> **보장 범위** — 오늘은 컨트롤러에 닿지 않고 404가 돌아왔다는 결과까지만 확인했다(내부 경로는 미검증).
````

각 개념 H3는 아래 순서로 쓴다.

1. `> **English Term** = 한 문장 정의`
2. "우리 코드에서는 …" 문장과, 지정 커밋의 실제 코드 3~6줄. 테스트 코드도 된다. 핵심 줄에는 `// 주석`을 단다. 발췌할 코드가 정말 없는 소절만 코드를 생략한다.
3. 동작 순서. `text` 블록에 `→`로 적는다.
4. 필요할 때만 비교 표와 기존 그림.
5. `> **보장 범위** — …` 박스 하나. 확인한 것과 미검증인 것을 구분한다. 소절 중간에 흩어진 한계와 단서는 이 박스로 모은다.

소절 구성 규칙:

- 개념 소절은 6~7개로 둔다. 8개 이상이면 가까운 것끼리 합치고, 내용은 버리지 않는다.
- 「보장 범위와 한계」나 「현재 코드 연결」 같은 모음 소절이 있으면 해체한다. 내용은 각 소절의 보장 범위 박스와 "우리 코드에서는" 부분으로 나눠 넣는다.
- 절 맨 앞의 용어표나 용어 색인은 지운다. 그 뜻은 각 소절 정의와 마지막 용어 한줄뜻으로 옮긴다.
- 비유는 쓰지 않는다. 기존 글에 비유가 있으면 코드와 연결되는 문장으로 바꾼다.
- 제목은 명사형으로 쓴다. 번호는 H2 `N.`, H3 `N)`이다. 개념어는 영어로만 쓰고 괄호 안에 한글을 병기하지 않는다.

## 용어 한줄뜻 (개념 절의 마지막 H3)

- 제목은 `### N) 용어 한줄뜻`이다. 제목 바로 아래 설명 문장 없이 `| 용어 | 한줄뜻 |` 표만 둔다.
- 용어 이름은 **영어**로 쓰고, 5~8개로 한다.
- 넣을 것: Spring, JPA, DB 접근의 이론·구조 용어.
  - 예: ORM, Entity, Persistence Context, First-Level Cache, Managed State, Dirty Checking, Snapshot, flush, Transaction Boundary, Schema Migration, Integrity Constraint, Repository
- 빼야 할 것:
  - 예외 클래스
  - `ResponseEntity`나 `Optional` 같은 API 타입, 개별 메서드
  - 라이브러리·제품 이름
  - Java 문법(`final`, checked 예외 등)
  - SQL 키워드
- 표 뒤에는 기존의 `> **더 볼 것**`을 둔다. 없으면 공식 문서 링크 2~3개를 넣는다.

## 코드 절

- 대표 코드블록 바로 뒤에 `**한 줄씩 보기**` 불릿을 단다. 핵심 줄마다 "무엇을 하고 언제 동작하는가"를 한 줄로 쓴다.
- `자동 검증 결과` 소절(또는 절)에서는 자동 테스트, 수동 확인, 미검증을 구분한다. 기존 결과와 커밋 링크는 그대로 둔다.

## 질문 절

- 형식은 `### N) 명사형 제목` → `**질문.** …` → `**A1.** …`이다.
- 오답 원문은 굵게 인용한 그대로 보존한다.
- 새 질문은 만들지 않는다.

## 마지막 절

- 첫 H3는 `### 1) 전체 흐름 다시 보기`다. 앞쪽에 있던 `dayNN-overview-*` 그림 블록(소개 문장, 이미지, 출처 줄)을 여기로 **옮기고**, 소개 1~2문장을 붙인다. 원래 자리에서는 지운다.
- 다음 H3는 `### 2) 이해의 변화와 남은 것`으로, 기존 정리 내용을 모은다.

## 작업 방식 (토큰 절약)

1. 근거 파일은 한 번씩만 읽는다.
2. 새 글 전체를 **Write 한 번**으로 쓴다.
3. 검수는 Grep 한 번으로 한다. 패턴: `^## |^### |^> \*\*[A-Z]|보장 범위|오늘의 흐름|이 글의 순서|overview`. 이 결과로 **개념 H3마다 정의 줄이 바로 뒤에 있는지** 확인한다. 빠졌으면 Edit로 그 줄만 넣는다.
