## 해결 기록

<!-- 해결한 부채는 위 표에서 지우지 말고 상태를 '해결(DayNN)'로 바꾼 뒤 이 절에 한 줄 요약을 남긴다. -->

- Day07 — 기존 ID 저장은 교체하고, 없는 예약은 `Optional`과 `ReservationNotFoundException`으로 바꿨다. Service 단위 테스트로 중복 미발생과 없는 ID 예외를 확인했다.
- Day07 — 404 응답과 500 내부 메시지 비노출을 예외 처리기 단위 테스트로 확인했다.
- Day07 — MockMvc로 예약 200, DTO 검증 400, 없는 예약 404, 경로 ID 검증 400의 MVC 계약을 확인했다.
- Day10 — `JpaReservationRepository`를 유일한 `@Repository` Bean으로 전환하고(`InMemoryReservationRepository`의 `@Repository`는 주석 처리) H2+Flyway로 영속화를 확인했다. 재시작 시 데이터가 사라지는 문제는 해소됐다(단, `spring.datasource.url`이 인메모리 H2라 JVM 프로세스 종료 시에는 여전히 사라진다 — 이건 별개로 "DB 서버가 파일/외부 DB인가"의 문제이며 이 트랙 범위 밖).
- Day14 — `V2__add_name_check_constraints.sql`로 `room_name`·`requester_name`에 `CHECK (... <> '')` 제약을 추가했다(`V1`은 손대지 않음). `entityManager.createNativeQuery()`로 Bean Validation을 우회한 직접 INSERT 테스트로, 빈 문자열이 이제 `PersistenceException`으로 거부됨을 확인했다.
- Day19 — `ReservationControllerHttpTest`에 `@Transactional`을 추가해 공유 인메모리 테스트 DB 오염을 막았다(25/25 통과). 사용자가 "학습자 코드를 대신 짜지 않는다" 규칙의 예외를 명시적으로 승인해 AI가 직접 수정.
- Day19 — `app/.idea/gradle.xml`에 `testRunner=GRADLE`을 추가해 IntelliJ 테스트 실행도 Gradle의 datasource 환경변수 오버라이드를 타도록 했다. 시스템 환경변수(prod DB 접속정보) 자체는 남아 있어 미해결로 표시.
- Day18·19 이월분(9/27) — `Member.reservations`에 `mappedBy` 컬렉션을 채우고 `PersistentBag` 초기화를 확인, `NPlusOneTest`를 `Statistics` 단언으로 교체. 커밋 `7a9626d`, 27/27 통과.
- Day21(9/29) — `findAllWithMemberOrNull()`(left join fetch)을 추가해 member 없는 예약이 목록에서 빠지지 않게 하고, `GET /reservations`를 `@Transactional(readOnly=true)` 서비스로 노출했다. 커밋 `094c6b3`, 30/30 통과.
- Day28(10/10) — `GlobalExceptionHandler.handleInvalidCredentials()`·`CustomAuthenticationEntryPoint`·`CustomAccessDeniedHandler` 세 곳의 401/403 응답에 `code`·`timestamp` 필드를 통일 추가했다. 기존 `error` 필드는 유지해 회귀 없이 51/51 통과. 커밋 `d38c973`.
- Day29(10/12) — `RequestIdFilter`가 모든 응답에 `X-Request-Id` 헤더를 붙여 요청 식별자를 확보했다(본문 필드 통합은 남겨둠).
