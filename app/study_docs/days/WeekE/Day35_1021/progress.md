## 2. 기술부채 최종 상태 (트랙 종료 시점)

5주 동안 쌓인 부채 중 "바로 고칠 것"은 전부 해소됐다(`기술부채.md` 해결 기록 참고). 트랙 종료 시점까지 남는 항목을 숨기지 않고 그대로 남긴다.

| 부채 | 분류 | 사유 |
|---|---|---|
| `startAt`/`endAt` 중 하나만 보내면 "시간대 없음"과 동일하게 조용히 무시된다(Day33) | 나중에 고칠 것 | 하나만 있으면 400으로 막아야 하지만, 겹침 검사 자체는 정상 동작해 우선순위를 낮춤 |
| 같은 방·같은 시간대 동시 요청에 대한 DB 레벨 exclusion constraint가 없다(Day33) | 고치지 않을 것 | 애플리케이션 레벨 검사만으로는 레이스 컨디션을 이론적으로 막지 못함 — H2·학습용 범위 밖, Testcontainers 스트레치와 연결된 문제 |
| JWT 만료 테스트가 실제 대기(`Thread.sleep`) 기반이다 | 나중에 고칠 것 | `Clock`을 주입해 시간을 앞당기는 방식으로 바꾸면 테스트가 더 빨라지고 결정적(deterministic)이 됨 — 현재는 테스트가 느려지는 정도의 영향만 있어 우선순위를 낮춤 |
| JWT는 로그아웃 시 서버 쪽에서 토큰을 무효화할 수단이 없다(stateless의 구조적 한계) | 나중에 고칠 것 | 블랙리스트(Redis 등) 또는 짧은 Access Token 만료 + Refresh Token 회전이 필요 — 이 트랙의 범위(단일 서버, 외부 저장소 없음)를 넘어섬 |
| Testcontainers 기반 통합 테스트와 실제 배포는 하지 않았다 | 고치지 않을 것 | 로드맵이 Week E 진입 시점부터 스트레치로 명시(§1) — 통합 테스트는 H2로 대체 |
| GitHub Actions의 일부 액션(Node 20 기반, `setup-java` v4 이전 버전 등)이 지원 종료 경고를 낸다 | 나중에 고칠 것 | 현재 빌드는 통과하지만, 향후 GitHub 측 강제 업그레이드 시점에 CI가 실패할 수 있어 액션 버전을 올려야 함 |
