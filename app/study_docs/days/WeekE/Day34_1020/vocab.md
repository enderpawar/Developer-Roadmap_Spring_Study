# Day34 (10/20, Week E D6) 용어

주제: 최종 인출 시험(전 범위, Week A~E) — 새 용어 없이 5주 전체 개념을 재정리

| 용어 | 한줄뜻 | 오늘 재확인 |
|---|---|---|
| 계층 분리(Controller/Service/Repository) | 요청 수신·비즈니스 규칙·저장을 서로 다른 책임으로 나누는 구조 | 문항 1 |
| DTO(record) vs Domain | DTO는 경계를 넘는 불변 데이터, Domain은 상태와 변경 규칙을 가진 가변 객체 | 문항 2 |
| Constructor Injection | 필요한 의존성을 생성자 매개변수로 받는 DI 방식 | 문항 3 |
| JPA의 추상화 대상 | 커넥션 풀이 아니라 매핑·SQL 생성을 대신 처리하는 것 | 문항 4 |
| 변경 감지(Dirty Checking) | flush 시점에 로드 스냅샷과 현재 값을 비교해 자동 UPDATE를 만드는 것 | 문항 5 |
| self-invocation | target 내부의 `this.메서드()` 호출은 프록시를 다시 통과하지 않아 `@Transactional`이 적용되지 않는 현상 | 문항 6 — **네 번째 도전 만에 근거 수준까지 안정** |
| 트랜잭션 전파(`REQUIRED`/`REQUIRES_NEW`) | 진행 중인 트랜잭션에 합류할지, 보류하고 새로 시작할지 정하는 규칙 | 문항 7 |
| Spring AOP 프록시 vs Hibernate LAZY 프록시 | 메서드 호출을 가로채는 것과 필드 접근을 가로채는 것은 다른 장치 | 문항 8 |
| N+1 Problem / Fetch Join | 목록조회 1번+연관조회 N번 vs JOIN 1번으로 묶어 조회 | 문항 9 |
| JWT stateless | 서버가 세션 상태를 저장하지 않고 토큰 자체로 인증을 검증하는 방식 | 문항 10 — **오답** |
| Unit/Slice/Integration 테스트 | 각각 순수 로직, 특정 계층 슬라이스(mock 포함), 실제 컨테이너 기동 범위가 다름 | 문항 11 — **오답** |
| 로그·민감정보 비노출 | 요청 추적(requestId)은 남기되 비밀번호·토큰 원문은 마스킹 | 문항 12 |
| Docker 멀티스테이지 빌드 | 빌드 단계와 실행 단계 이미지를 분리해 최종 이미지에 빌드 도구를 남기지 않는 것 | 문항 13 — **오답** |
| 구간 겹침 판정(부등호) | 등호 없는 `<` 비교로 맞닿는 경계를 겹침에서 제외 | 문항 14(Day33 즉시 재시험) |

## 이번 시험에서 드러난 패턴

Week A~C 항목(1~9번)은 여러 차례 재시험을 거쳐 힌트 없이 안정됐다. 흔들린 세 문항(10·11·13번)은 전부 Week D~E에서 새로 배운 내용이었고, 공통점은 "장치의 목적을 다른 목적과 혼동"했다는 것이다 — stateless를 만료시간 문제로, 슬라이스 테스트의 mock 범위를 실수로, 이미지 축소 이유를 빌드 속도로 착각했다.
