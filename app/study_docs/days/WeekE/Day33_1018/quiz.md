## 2. 세션 예측과 교정 — 구간 겹침 검사

| # | 질문 | 학습자 답 | 판정 | 교정 |
|---|---|---|---|---|
| P1 | `startAt`/`endAt`을 엔티티에 추가하면 `ddl-auto: validate`가 V7 컬럼과 일치를 확인해줄 것인가 | "그럴 것 같다, 컬럼명만 맞추면" | ✅ | 첫 실행부터 통과, `--info` 로그로 `start_at`/`end_at` 매핑 확인 |
| P2 | 맞닿는 구간(10~11시, 11~12시)은 겹침으로 판정되는가 | "겹침 공식이 부등호라서 안 겹칠 것 같다" | ✅ | `reserveAllowsTouchingIntervalsInSameRoom` 예외 없이 통과로 확인 |
| P3 | 기존 `reserve(roomName, requesterName)` 호출부를 하나도 안 고쳐도 통과하는가 | "시간대가 없으면 새 로직이 아예 안 들어가니까 그대로 될 것" | ✅ | 기존 61개 테스트 무수정 통과 |
| P4 | 취소된 예약도 겹침 검사에 포함해야 하는가 | "브리프에 없는 조건이라 굳이 안 넣어도 되지 않나" | ❌ | `cancel()`이 `confirmed`를 `false`로 되돌리는 기존 규칙과 맞춰보면, 취소된 예약이 계속 새 예약을 막는 건 명백히 잘못된 동작. `confirmed = true` 조건 추가로 교정 |
| P5 | `startAt`/`endAt`을 `@NotNull` 필수로 걸 것인가 | "그냥 필수로 걸면 검증이 간단하니까 걸자" | ❌ | 걸어보니 시간대 없이 예약하던 기존 테스트 8개가 전부 400으로 깨짐. "둘 다 있을 때만 검사한다"는 선택 필드 설계로 교정 |
