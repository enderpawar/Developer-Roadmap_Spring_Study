## 2. 세션 예측과 교정 — CI

| # | 질문 | 학습자 답 | 판정 | 교정 |
|---|---|---|---|---|
| P1 | `docker` 잡이 `test` 잡 없이도 동시에 실행되게 하면 무슨 문제가 생기는가 | "테스트가 실패해도 이미지 빌드·기동 검증에 시간을 더 쓰게 된다" | ✅ | 정확 — `needs: test`로 순서를 강제해 낭비를 막음 |
| P2 | 로컬 `./gradlew test`가 계속 통과했는데 실제 MySQL에서 `V1__init.sql`이 실패할 수 있는가 | "로컬 테스트가 다 통과했으니 실제 MySQL에서도 별문제 없을 것 같다" | ❌ | 실제로 1차 CI 실행에서 Error 1064로 실패했다. H2 `MODE=MySQL`은 진짜 MySQL과 100% 같은 파서가 아니라는 것을 이번에 실증으로 확인 |
| P3 | 1064 오류 메시지에서 어떤 부분이 원인 지점을 정확히 가리키는가 | "`near '--Java는 CamelCase...'` 부분이 문제가 된 위치를 보여준다" | ✅ | 정확 — MySQL은 `--` 뒤 공백이 없으면 주석으로 인식하지 않고 그 뒤 텍스트를 SQL 토큰으로 파싱하려다 실패 |
| P4 | 마이그레이션 체크섬이 바뀌는 게 이번엔 왜 문제가 안 됐는가 | "이번이 MySQL에 V1이 처음 적용되는 거라 아직 적용 이력이 없어서" | ✅ | 정확 — 운영 MySQL에 V1이 적용된 적이 없고, 테스트는 매번 새로 만들어지는 H2라 체크섬 불일치가 발생할 이력 자체가 없음 |
