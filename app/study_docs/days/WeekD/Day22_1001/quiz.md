## 2. 세션 예측과 교정 — BCrypt

| # | 질문 | 학습자 답 | 판정 | 교정 |
|---|---|---|---|---|
| P1 | 같은 원문을 `encode()`로 두 번 호출하면 결과가 같은가 | "다를 것 같다. salt가 랜덤이라고 들었다" | ✅ | `firstHash`, `secondHash`가 실제로 달랐음(`assertNotEquals`) |
| P2 | 해시 문자열이 어떤 형태로 시작하는가 | "`$2a$10$`일 것 같다" | ✅ | 버전(`2a`) + strength 기본값(`10`) 조합 |
| P3 | `matches(원문, 해시)`가 원문 앞뒤 공백까지 정확히 구분하는가 | "공백까지 정확히 일치해야 true일 것 같다" | 미검증 | 오늘 테스트엔 공백 케이스가 없어 확인하지 않음 — 추측일 뿐 사실 아님 |
| P4 | `PasswordEncoderConfig`로 Bean을 만들지 않고 `new BCryptPasswordEncoder()`를 직접 써도 되는가 | "Bean으로 등록해야 여러 클래스에서 같은 정책을 주입받을 수 있다" | ✅ | DI 없이 매번 new하면 나중에 구현체(예: strength 상향)를 한 곳에서 바꾸기 어려움 |
